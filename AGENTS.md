## Project rules
- You work on Windows 11, from the Visual Studio Code extension for Codex.
- All explicit project rules from the user must be added to AGENTS.md by Codex, unless they can be trivially deduced from the code, documentation or tasks.md.
- Before starting work, review `TASKS.md`, pick the first unfinished task in order, and attempt to complete that task before starting any later task.
- If an external source is used to provide us with raw data, use it only to populate or refresh a local cache; normal layer builds must read the cache and must not reload them from an external source on every run.
- When invoking GDAL/OSGeo tools on this machine, use explicit binaries from `C:\OSGeo4W\bin` (or from `OSGEO4W_BIN` when set).
- Prefer OpenStreetMap-derived data for thematic overlays where useful (including airfields and other special features), and prioritize OSM-informed terrain/landuse inputs when improving hex-cell shading quality; do not treat this as overriding the current administrative boundary stack unless a task explicitly requests boundary-source changes.
- Model airports/airfields as points of interest (POI) rather than logistics-network links; keep logistics layers focused on ground-interdictable networks.
- POI icon style rule: prefer clear OSM-like cartographic pictograms (readable civilian map symbols) over austere/NATO-style military symbology unless a task explicitly requests military-standard notation.
- POI bridge selection rule: include only strategically relevant bridges (crossings over major rivers/long water barriers); exclude minor stream crossings that are easily bypassed.
- POI civilian-port rule: include `port_civil` only when the port is within 5 km of a `city|town` settlement with population `>= 100,000`.
- POI first-attempt scope rule: include only (a) military airfields, (b) major airfields (`airport_large`), (c) nuclear power plants, (d) strategic bridges over major rivers/long water barriers, (e) civilian ports per the 5 km/100k rule, (f) major industrial facilities excluding sugar refineries, (g) missile/ballistic strategic military facilities, plus (h) Azovstal as an explicit historic override. Exclude dams and non-nuclear power plants from POI in this first attempt.
- Preserve source metadata fields for POI classification (including `aerodrome:type` and other raw tags used in mapping rules) in processed outputs so rules can be revised without refetching source data.
- Settlement label formatting rule: render English transliterations in parentheses only when `nameEn` is present and non-empty; never show empty `()` suffixes.
- For targeted river reconstruction during processing, prefer elevation-guided path selection; if elevation data is unavailable, use river-line shape and dominant direction as the fallback guide (not exact centerline placement).

- For inland wetland enhancement (Task 76), use processed `water-bodies` as the primary corridor mask to prioritize wetland recovery near mapped river/water corridors rather than broad non-river inland expansion.
- For quick `--hex-only` tests, prefer geographically nearby hexes to keep the combined bbox small; warn when selected test hexes are spread far apart because it significantly increases tiled fetch/build time.
- Overpass tiled-fetch reliability rule: treat timeout/error payloads (including JSON `remark` runtime-timeout responses) as invalid, do not cache invalid tile payloads, collect failed tiles during the first pass, then wait 10 seconds and retry failed tiles with single-worker behavior before unresolved fallback/failure handling.
- Render built-up urban fill from Natural Earth urban areas for settlements with `max_pop_al >= 50,000`, anchored to nearby `place=city|town` settlements with `population >= 50,000`, to improve visual coverage for medium cities while suppressing unlabeled/townlet artifacts.
